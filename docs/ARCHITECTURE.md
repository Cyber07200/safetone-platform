# Архитектура SafeTone

## Pipeline

`services/pipeline.py` исполняет этапы последовательно и после каждого записывает в
`processing_runs.stages` статус (`pending → running → completed | failed | skipped`), метод, сводку,
длительность и предупреждения. UI опрашивает `GET /api/v1/process/{id}` и показывает реальное состояние.
Любое исключение → `result_status=FAILED`, этап отмечен `failed`, последующие — `skipped`, финального ответа нет.

| Этап | Demo | Live |
|---|---|---|
| Генерация | `demo_scenario` / `user_provided` | `llm:<provider>` через AIRouter |
| Извлечение утверждений | предложения + парсер фактов (`legal/claims.py`, `knowledge/facts.py`) | то же |
| Поиск источников | BM25 по чанкам банка + общим нормативным (`knowledge/retrieval.py`) | то же |
| Юр. проверка | доказательный движок (`legal/verifier.py`) | + LLM-верификатор с валидацией цитат (если разрешено) |
| Юр. корректировка | политика рисков (`legal/policy.py`, `legal/engine.py`) | то же |
| Лингвистика | офлайн-редактор (`linguistic/rewriter.py`) | LLM-редактор → fallback офлайн |
| Проверка смысла | `linguistic/semantic.py` | то же; при провале — откат |

## Legal Assurance Engine

1. **Утверждения.** Ответ делится на предложения; служебные фразы (приветствия, вопросы) не проверяются.
   Для каждого извлекаются значения (%, ₽, дни, рабочие дни, месяцы, «без комиссии») и их **предмет**
   (ставка/комиссия/лимит/льготный период… + уточнения: наличные, покупки, досрочное погашение…).
   Срок рядом со ставкой («на 6 месяцев — 14%») — условие, а не отдельный факт.
2. **Источники.** BM25 с русским стеммингом и нормализацией синонимов; фильтр по банку и продукту.
3. **Сравнение значений.** Кандидат из источника подходит, если совпадают единица и предмет, нет
   конфликта уточнений, особых случаев (досрочное расторжение, наличные…) и условий (срок вклада).
   Совпадение с действующим источником → CONFIRMED; расхождение → CONTRADICTED с заменой значения;
   несколько равновероятных значений → UNVERIFIED; только неактуальные источники → OUTDATED_SOURCE;
   нет кандидатов → UNVERIFIED.
4. **Утверждения без чисел.** Доля совпадения терминов с предложением источника ≥ 60% → проверка
   полярности (отрицания) и абсолютных формулировок против исключений в источнике.
5. **Приоритет актуальности.** Действующий документ всегда важнее; совпадение со старой версией
   фиксируется в аудите как `matches_outdated`. Актуальность = статус + даты действия, не дата загрузки.
6. **Политика рисков.** LOW — без изменений; MEDIUM — осторожная оговорка; HIGH — исправление по источнику,
   иначе удаление + NEEDS_REVIEW + «каких данных не хватает»; CRITICAL — безопасный черновик и обязательная
   проверка. Юридические вопросы (односторонний порядок, суд, законность…) → NEEDS_REVIEW для неподтверждённого.
7. **Корректировка** использует только значения и формулировки из источников; оговорки фиксированные и не содержат фактов.

Признаки формы («обещание», «абсолютная формулировка», «ссылка на нормы») никогда не блокируют ответ
сами по себе — они только калибруют риск утверждения, которое не подтверждено источником.

## AI Layer (GigaChat)

`AIProvider` (`services/ai/base.py`): `is_configured`, `missing_config`, `complete()` с тайм-аутом,
классификацией ошибок (retryable: timeout, сеть, 408/409/425/429/5xx), учётом токенов и стоимости.
Единственный адаптер — `GigaChatProvider` (OAuth с кэшем токена, TLS с сертификатами НУЦ Минцифры).
Слой провайдеров оставлен абстрактным: другая модель = класс-наследник + регистрация в `build_providers`.

`AIRouter`: ранжирование, ручной выбор, последовательный fallback, повторы с backoff, circuit breaker,
журнал попыток (`ai_calls` в аудите: задача, провайдер, модель, результат, задержка, причина выбора).

## Данные

- `banks`, `products`, `bank_settings` — мультибанковость и настройки обработки.
- `documents` — банк (или NULL = общий нормативный), продукт, `document_key` + `version`, тип, дата,
  `effective_from/to`, `actuality_status`, ссылка, sha256, флаги безопасности; `chunks` — фрагменты с разделом/страницей.
- `processing_runs` — полный снимок обработки: вопрос, исходный/юридический/финальный ответ, провайдер,
  модель, этапы, утверждения, источники, изменения, лингвистика, проверка смысла, вызовы AI, ошибки.

## Чат-ассистент (`services/chat.py`)

- **Доступ к БД.** Перед каждым ответом BM25-поиск по базе знаний (законы РФ + документы банка) по новому
  сообщению и предыдущему вопросу; найденные фрагменты уходят в GigaChat блоками `<source>` и сохраняются
  с ответом. Документы банка — только при `allow_documents_to_llm`; законы — всегда; фрагменты с признаками
  prompt injection — никогда.
- **Память.** Последние `CHAT_HISTORY_WINDOW` сообщений передаются дословно; более старые сворачиваются
  GigaChat в краткую «память» (зашифрованная `summary_enc`), которая идёт в системный промпт.
- **Demo.** Без ключа — ответ из найденных норм, явно помеченный; память не используется.
- **Владелец.** Браузер хранит случайный токен (localStorage) и шлёт его в `X-Chat-Owner`; в БД — только
  HMAC-SHA256. Чужой диалог неотличим от несуществующего (404).

## Банк «Ясный Берег» (DEMO)

Установка содержит один вымышленный банк (`seed/demo_data.py`, slug `yasny-bereg`): 7 продуктов и 14 документов
(тарифы, договоры, общие условия, история банка, порядок жалоб, правила безопасности, FAQ). Прежние демо-банки
удаляются при старте (`retire_old_demo_banks`); банк для проверки изоляции создаётся только в тестах.
Ассистент получает название банка и список продуктов из БД (`chat._system`), источники подбираются так, что
документы банка идут первыми (до 4), законы — дополнением (до 3); устаревшие редакции не используются.

## Проверка документов в чате (`services/chat_files.py`)

PDF/DOCX/TXT/MD/HTML читаются локально; фото (JPG/PNG) и сканы PDF — GigaChat (`/files` → сообщение с
`attachments` → `/files/{id}/delete` сразу после распознавания). Тип проверяется по сигнатуре, лимит 10 МБ.
Текст документа сверяется детерминированным юр. движком (`legal.engine.analyze`) с продуктом, определённым по
названию в тексте (`chat.detect_product`); результаты (`findings`) и распознанный текст хранятся зашифрованными
(`attachment_enc`, `findings_enc`, миграция 0003). GigaChat получает документ, findings и источники и пишет разбор.
В Demo — отчёт только по findings. Последний документ диалога повторяется в следующих вопросах (6 000 символов).

## Шифрование истории (`core/crypto.py`)

AES-256-GCM; ключ каждого диалога выводится HKDF-SHA256 из мастер-ключа `CHAT_ENCRYPTION_KEY` (только в
`.env`, не в БД); AAD привязывает шифротекст к записи (`<id сообщения>:<роль>`), поэтому подмена или
перенос шифротекста обнаруживается; nonce случайный. Шифруются тексты, заголовки, сводки и списки
источников. Хэширование для содержимого не подходит: ассистент должен читать историю.
**Потеря ключа = потеря истории**, ключ нужно хранить в резервной копии.

## База данных (Supabase)

PostgreSQL 17 в Supabase (проект `safetone`, eu-central-1), подключение через Session pooler
(`DATABASE_URL`). Миграция `0002` включает Row Level Security на всех таблицах и отзывает права у ролей
`anon`/`authenticated`: публичный REST API Supabase не видит данных, доступ есть только у backend.
Локально по-прежнему работает SQLite.

## Законы

`seed/laws/*.md` — тексты 395-1, 353-ФЗ, 177-ФЗ, 161-ФЗ, 230-ФЗ, 2300-1 и глав 42/44/45 ГК РФ в действующей
редакции (по данным ГАРАНТ, дата в заголовке файла). `scripts/fetch_laws.py` обновляет тексты;
`seed_laws` при старте загружает новые/изменённые как новую версию документа (старая → superseded).

## Frontend

React 18 + TypeScript + Vite + Tailwind + React Router + TanStack Query + Framer Motion.
`BankProvider` — выбранный банк; `useRun` — polling реального состояния; `ResultView` — результат/аудит;
`AuditView` — 12 разделов аудита; `PipelineProgress` — этапы; `DiffText` — подсветка изменений.
Анимации учитывают `prefers-reduced-motion` (MotionConfig + CSS).
