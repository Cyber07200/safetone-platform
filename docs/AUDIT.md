# Аудит исходного проекта SafeTone (safetone.zip)

## Карта исходной архитектуры

| Файл | Роль |
|---|---|
| `app.py` | FastAPI, единственный эндпоинт `POST /ask` → `ask_gpt` → `process_response` |
| `yandex_gpt.py` | генерация YandexGPT с RAG-контекстом, «GPT-юрист» (`check_with_gpt`), упрощение (`simplify_with_gpt`) |
| `checker.py` | уровень 1 — `guidelines.check_text` (подстроки), уровень 2 — GPT-юрист, запись лога в JSON |
| `guidelines.py` | 21 правило `RULES` с ключевыми словами и `safe_reply` |
| `knowledge_base.py` | ChromaDB, нарезка по 300 символов, загрузка DOCX (через `pandoc`) и HTML |
| `chat.py`, `dashboard.py` | Streamlit-чат клиента и дашборд лога |
| `test_*.py` | ручные скрипты с живыми вызовами API (не автотесты) |
| `Raschetny_schet.docx`, `Общие условия кредитования.html` | исходные документы |
| `ssh-key-*`, `safetone_log.json`, `__pycache__/` | артефакты в архиве |

React-фронтенда в архиве не было.

## Найденные проблемы

### Критичные (безопасность)
1. **Реальный API-ключ Yandex Cloud и folder ID зашиты в `yandex_gpt.py`.** Ключ нужно отозвать.
2. **Приватный SSH-ключ** (`ssh-key-1776080404655`) лежит в архиве проекта. Нужно отозвать на сервере.
3. Публичный IP сервера зашит в `chat.py`, HTTP без TLS.

### Логика проверки
4. `guidelines.py` содержит правила **договора поставки товаров** (приёмка, гарантия, доставка, факсимиле),
   не относящиеся к ответам банка клиенту; совпадение подстроки («без оплаты», «не нужно подписывать»…)
   **блокирует весь ответ** без анализа контекста — источник ложных блокировок.
5. «GPT-юрист» работает fail-open: при ошибке API или непарсимом JSON возвращает `violation: false`,
   и ответ считается безопасным.
6. Ошибка генерации (`"Ошибка API: 401 — …"`) возвращается клиенту как ответ банка.
7. Проверка не опирается на источники: RAG используется только в генерации; юрист проверяет по 10
   абстрактным правилам в промпте. Нет статусов утверждений, уровней риска, оснований исправлений.
8. Промпт генерации требует «не говорить, что информации нет, если есть хоть что-то по теме» — провоцирует
   выдумывание.
9. Упрощение не проверяется на сохранение смысла.

### Инженерные
10. Нет таймаутов HTTP, bare `except:` повсюду, дублирование кода запросов.
11. Лог — JSON-файл, перезаписываемый целиком (гонки, рост), нет БД и миграций.
12. Нет дат актуальности и версий документов; ID фрагментов `{name}_{i}` конфликтуют при повторной загрузке.
13. PDF не поддерживается; DOCX через внешний `pandoc` в subprocess.
14. Нет `requirements.txt`, нет автотестов.

## Что сделано

- Секреты удалены из кода, добавлены `.env.example`, `.gitignore`, маскирование в логах, тест на отсутствие ключей в исходниках.
- `guidelines.py`, `check_text`, статусы `BLOCKED_L1/L2` удалены полностью; регрессионные тесты
  (`tests/test_rules_removed.py`) доказывают, что безобидные ответы с прежними «ключевыми словами» проходят.
- Вместо фильтров — доказательная проверка утверждений по источникам с 5 статусами и 4 уровнями риска,
  соразмерная политика обработки, fail-closed при ошибках (FAILED, а не «успех»).
- Исходные документы сохранены как справочные источники с неподтверждённой актуальностью.
- Streamlit-интерфейсы заменены React-приложением (лендинг, Workspace, аудит, история, база знаний, модели, настройки).
