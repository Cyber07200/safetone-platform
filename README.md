# SafeTone — Legal & Linguistic Assurance для банковских AI-ассистентов

> **Юридическая точность. Понятный язык. Доверие в каждом ответе.**

SafeTone принимает ответ готовой языковой модели (YandexGPT, GigaChat, любая OpenAI-совместимая),
проверяет каждое существенное утверждение по договорам, тарифам и нормативным источникам банка,
исправляет ошибки **только на основании источника**, переписывает ответ понятным языком и
проверяет, что упрощение не изменило юридический смысл. Каждое решение сохраняется в аудит.

SafeTone **не является** собственной языковой моделью и **не является** юридической консультацией.
MVP не сертифицирован и не заявляет соответствия регуляторным требованиям.

## Быстрый старт (macOS)

Нужны **Python 3.11+** (проверено на 3.11, совместимо с 3.12–3.14) и **Node.js 20+**.

```bash
unzip safetone-platform.zip && cd safetone-platform
./start.sh
```

Скрипт создаст `backend/.venv`, установит зависимости, скопирует `.env.example → .env`
(Demo Mode), применит миграции, запустит backend и frontend:

- приложение: <http://127.0.0.1:5173>
- OpenAPI / Swagger: <http://127.0.0.1:8000/docs>

API-ключи для запуска не нужны.

### Ручной запуск

```bash
# backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
alembic upgrade head          # миграции (также применяются автоматически при старте)
uvicorn app.main:app --reload --port 8000

# frontend (в другом терминале)
cd frontend
npm install
npm run dev                   # http://127.0.0.1:5173 (проксирует /api на :8000)
```

Один процесс для показа: `make serve` — собирает frontend, и backend раздаёт его на <http://127.0.0.1:8000>.

### Тесты

```bash
make test            # или по отдельности:
cd backend && pytest -q
cd frontend && npm test
```

## Demo Mode и Live Mode

| | Demo Mode | Live AI Mode |
|---|---|---|
| Нужны ключи | нет | да, хотя бы один провайдер |
| Исходный ответ | заранее подготовленный сценарий **или** ответ, вставленный пользователем | генерация выбранной моделью (или вставленный ответ) |
| Юридический слой | выполняется по-настоящему (доказательная проверка по базе знаний) | то же + LLM-верификация (если разрешена передача документов) |
| Лингвистический слой | офлайн-редактор (словарь стиля) | LLM-редактор, при ошибке/искажении смысла — офлайн-редактор |
| Маркировка | `DEMO MODE`, в аудите — «Заранее подготовленный демо-сценарий», провайдер «не использовались» | фактический провайдер и модель, токены, задержка, все попытки вызовов |

Demo Mode никогда не выдаёт подготовленный текст за генерацию модели: этап «Генерация»
имеет метод `demo_scenario` и прямую подпись «Это не генерация языковой модели».

**10 демо-сценариев** (Workspace → «Готовый сценарий»):

1. Безопасный ответ — проходит без изменений (фраза «без оплаты», которую блокировал старый rules, подтверждается тарифом)
2. Ошибка в процентной ставке — 19,9% → 29,9% по тарифу
3. Неверное утверждение о комиссии — «без комиссии» заменяется формулировкой тарифа
4. Противоречие договору — верная часть сохраняется, два утверждения исправляются по п. 5.1–5.2
5. Неполные данные — ставки на 24 месяца нет в источниках: значение не выдумывается, NEEDS_REVIEW
6. Неоднозначный юридический вопрос — абсолютная формулировка против договора с исключением, экспертная проверка
7. Критичный риск: обещание одобрения — исправлено по договору, но обязательна ручная проверка
8. Упрощение без изменения смысла — канцелярит убран, «7 рабочих дней» и все условия сохранены
9. Устаревший тариф — 490 ₽ совпадает только с заменённой версией, исправлено на 690 ₽ из действующей
10. Источник без подтверждённой актуальности — только пересказ закона → OUTDATED_SOURCE

Также можно проверить **любой свой ответ**: «Проверить свой ответ AI» → вопрос, продукт, текст ответа.

### Переключение Demo / Live

- `SAFETONE_MODE=demo|live` в `backend/.env` — режим по умолчанию.
- В Workspace переключатель «Режим AI». Live активен только если настроен хотя бы один провайдер;
  без ключей API возвращает `409 LIVE_MODE_UNAVAILABLE` с предложением перейти в Demo.

## Подключение реальных AI API

Все ключи — только в `backend/.env` (файл в `.gitignore`). После изменения перезапустите backend.
Статус провайдеров — страница «Модели» (кнопка «Проверить доступность» делает реальный короткий запрос).

### YandexGPT (Yandex AI Studio)

1. Создайте сервисный аккаунт с ролью `ai.languageModels.user`, выпустите API-ключ.
2. В `.env`:
   ```
   YANDEX_API_KEY=<ключ>
   YANDEX_FOLDER_ID=<id каталога>
   # опционально, по умолчанию gpt://<folder>/yandexgpt-lite/latest
   YANDEX_MODEL_URI=gpt://<folder>/yandexgpt/latest
   ```
   Используется `POST https://llm.api.cloud.yandex.net/foundationModels/v1/completion`,
   заголовок `Authorization: Api-Key …` (или `YANDEX_IAM_TOKEN` → `Bearer`).

### GigaChat

```
GIGACHAT_AUTH_KEY=<Authorization key из личного кабинета>   # или CLIENT_ID + CLIENT_SECRET
GIGACHAT_SCOPE=GIGACHAT_API_PERS        # B2B: GIGACHAT_API_B2B / GIGACHAT_API_CORP
GIGACHAT_MODEL=GigaChat
```
OAuth: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` (токен 30 минут, кэшируется).
Чат: `GIGACHAT_BASE_URL/chat/completions`, по умолчанию `https://api.giga.chat/v1`
(прежний `https://gigachat.devices.sberbank.ru/api/v1` можно указать в `GIGACHAT_BASE_URL`).
Если TLS-проверка не проходит — укажите путь к сертификату НУЦ Минцифры в `GIGACHAT_CA_BUNDLE`.

### OpenAI-совместимые провайдеры

```
OPENAI_API_KEY=...
OPENAI_BASE_URL=https://<host>/v1
OPENAI_MODEL=<model>
OPENAI_PROVIDER_LABEL=<название для UI>
```

### Маршрутизация

`DEFAULT_AI_PROVIDER=auto|yandex|gigachat|openai`. В режиме `auto` AI Router ранжирует
**настроенные** провайдеры по поддержке задачи, приоритету банка (экономия / баланс / качество),
цене из `*_COST_PER_1K_TOKENS` (цены вашего договора; неизвестная цена считается нейтральной) и
наблюдаемой задержке. Вызовы последовательные (не параллельные), ограниченные повторы
(`AI_MAX_RETRIES`) на тайм-ауты/429/5xx, fallback на следующий провайдер, circuit breaker после 3 ошибок подряд.
Это политика на основе известной конфигурации — она не гарантирует самую дешёвую или лучшую модель.

**Передача документов банка во внешние модели** по умолчанию выключена (Настройки → «Передавать документы
банка во внешние LLM»). Без неё LLM получает только вопрос, а проверка идёт доказательным движком локально.

### REST API (основное)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | состояние, доступность Live |
| POST | `/api/v1/process` | запуск обработки (202 + polling; `wait: true` — синхронно) |
| GET | `/api/v1/process/{id}?bank_id=` | реальное состояние этапов и полный аудит |
| POST | `/api/v1/process/{id}/rerun?bank_id=` | повторный запуск |
| GET | `/api/v1/history?bank_id=&status=&mode=&risk=&q=` | история с фильтрами и пагинацией |
| GET/POST | `/api/v1/documents` | список / загрузка (multipart, PDF/DOCX/HTML/TXT/MD, ≤10 МБ) |
| GET/PATCH/DELETE | `/api/v1/documents/{id}?bank_id=` | документ с фрагментами / актуальность / удаление |
| GET | `/api/v1/banks`, `/api/v1/products`, `/api/v1/scenarios` | каталог |
| GET | `/api/v1/providers`, POST `/api/v1/providers/{name}/check` | провайдеры и проверка |
| GET/PUT | `/api/v1/settings?bank_id=` | настройки банка |
| GET | `/api/v1/stats?bank_id=` | показатели для обзора |

Ошибки: `{"error": {"code", "message", "details"}}`.

### База данных

SQLite (`backend/safetone.db`) для локального запуска, PostgreSQL для production:
`DATABASE_URL=postgresql+psycopg://user:pass@host:5432/safetone` и `pip install "psycopg[binary]"`.
Схема создаётся миграциями Alembic (`backend/alembic/versions/0001_initial_schema.py`).

## Безопасность (MVP)

- Ключи только в `backend/.env`; `.env` в `.gitignore`; `.env.example` без значений; ключи не попадают
  во frontend, историю и журналы; фильтр логов маскирует `Api-Key`, `Bearer`, `Basic`, значения секретов.
- Загрузка: белый список форматов, проверка сигнатуры содержимого (PDF/DOCX), защита от zip-bomb,
  лимит размера, имя файла очищается, файл сохраняется под UUID (защита от path traversal),
  HTML-скрипты удаляются, из документов ничего не исполняется, дубликаты отклоняются.
- Prompt injection: инструкции системы отделены от данных (`<source>`/`<question>` блоки),
  подозрительные фрагменты помечаются и никогда не передаются во внешние LLM; ответы LLM-верификатора
  принимаются только с цитатой, подтверждённой по тексту источника.
- Изоляция банков: документы/история/настройки фильтруются по `bank_id`; чужие объекты — 404.
- Лимиты длины вопроса/ответа, общий лимит тела запроса 12 МБ, заголовки `nosniff`, `DENY`, `no-referrer`.
- Хранение данных: история хранится `retention_days` дней (настройка банка, по умолчанию 90), удаляется при старте сервера.

## Известные ограничения MVP

- **Юридическая база демо-версии:** законы представлены справочными пересказами без подтверждённой
  актуальности (статус `unverified`). Проверки «по действующему законодательству» нет, пока банк не
  загрузит официальные тексты с подтверждённой актуальностью.
- **Доказательный движок** работает на уровне предложений: извлекает ставки, суммы, сроки, комиссии и их
  предмет, сравнивает с источниками, проверяет полярность и абсолютные формулировки. Сложные
  многосоставные условия, диапазоны («от X до Y») и перефразирование без общих слов распознаются
  хуже — такие утверждения получают UNVERIFIED и не подтверждаются ложно.
- **Поиск** лексический (BM25 со стеммингом и нормализацией синонимов). Векторный поиск можно добавить
  через тот же интерфейс `search()`.
- **Live-адаптеры** написаны по официальной документации (09.2026) и покрыты тестами на mock-транспорте,
  но **не проверялись на реальных ключах** в этой сборке. Эндпоинты вынесены в `.env`.
- Нет аутентификации пользователей и ролей (банк выбирается в интерфейсе) — обязательна перед внедрением.
- Фоновая обработка выполняется внутри процесса (asyncio); для нагрузки — вынести в очередь задач.
- Сканированные PDF без текстового слоя (OCR) не поддерживаются.
- Офлайн-редактор использует словарь стиля; глубокое перефразирование доступно в Live через LLM.

## Исходный проект

Материалы предыдущей версии (DOCX «Расчётный счёт», HTML «Общие условия кредитования») перенесены в
`backend/app/seed/legacy/` и загружаются как справочные документы с неподтверждённой актуальностью.
Старый код (`guidelines.py`, `checker.py`, Streamlit-интерфейсы) заменён; причины — в [docs/AUDIT.md](docs/AUDIT.md).
